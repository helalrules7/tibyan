# أداة المراجعة وطريقة العمل

كل نص علمي يدخل التطبيق (أسباب النزول، المناسبات، الوجوه والنظائر…) يمر بهذه الطريق. السكربت يقسّم الكتاب ويقترح الربط بالآيات فقط، ولا يكتب نصا ولا يغيّره. وشخص يراجع كل مدخل قبل أن يصل إلى أي حزمة.

## الطريق باختصار

1. **الاستيراد** (`tools/import_*.py`): يجلب ملف المصدر ويتحقق من بصمته (SHA-256)، ويقسمه بأقسام الكتاب نفسه، ويقترح الربط بالآيات مع درجة ثقة، ويكتب كل شيء **مسودات** في ملف مراجعة `data/review/<الكتاب>.review.db`.
2. **المراجعة** (`apps/review/`، أداة ويب): تعرض كل مسودة بجانب الآية بنص المصحف الحقيقي (من `content.db`)، ويسجل كل إجراء باسم صاحبه ودوره.
3. **التصدير** (`tools/export_pack.py`): يبني حزمة SQLite فيها **المراجَع فقط**، مع فهرس (العدد، والمراجعون، والبصمة)، ثم commit مستقل من نوع `data(...)` وسطر في `docs/DATA_SOURCES.md`.
4. **التطبيق**: الميزة المخفية لا تظهر إلا إذا كان مفتاحها في `assets/config/feature_flags.json` مفعلا **و** حزمتها المراجعة موجودة.

## الحالات والقواعد

```
مسودة ──إرسال──▶ قيد المراجعة ──اعتماد──▶ مراجَع
  ▲                  │  (المراجع غير المحرر)     │
  └──── رد بملاحظة ──┘                          │
  ▲                                              │
  └──────────────── رد بملاحظة ─────────────────┘
أي تعديل على مدخل مراجَع يعيده إلى «قيد المراجعة».
```

| الدور | يستطيع |
|---|---|
| محرر | تعديل الربط والصفحات والملاحظة، وإرسال المسودة للمراجعة |
| مراجع | اعتماد ما هو قيد المراجعة، أو رده إلى المسودات **بملاحظة مكتوبة** |
| مشرف | الاثنين معا |

- **لا يعتمد أحد عملا هو محرره**، ولو كان مشرفا. والقاعدة مكتوبة في مخطط قاعدة البيانات نفسه، فلا يمكن تجاوزها من خارج الأداة.
- **نص الكتاب لا يُعدَّل في الأداة**. خطأ في التقسيم أو فرق عن المطبوع يُكتب في الملاحظة، ويُصلح بإعادة الاستيراد.
- **سجل الإجراءات لا يُحذف ولا يُعدَّل** (محمي في المخطط أيضا). والمدخلات لا تُحذف.
- لكل مدخل **بصمة محتوى** (النص، ومكانه في الطبعة، والآيات المربوطة). يسجلها الاعتماد، ويعيد التصدير حسابها: إن تغير شيء بعد الاعتماد يرفض التصدير.

## ما يحفظه كل مدخل

صف المصدر (الكتاب، والطبعة، والناشر، والمحقق، والترخيص، ورابط الملف وبصمته)، ومكانه في تلك الطبعة (الجزء والصفحة)، ونصه كما هو، وربطه بالآية أو الآيات أو كلمات من آية، ومن أنشأه (سكربت أو شخص) وثقة السكربت وأساسها، والمحرر، والمراجع، والتواريخ، والملاحظات، وبصمة المحتوى. المخطط: `tools/review_schema.sql`.

أساس الربط:
- `marker+quote`: رقم الآية المطبوع في الكتاب ونص الاقتباس متفقان (ثقة 0.95).
- `quote`: وُجد الاقتباس في آية واحدة من السورة (0.75)، أو خالف الرقمَ المطبوع (0.6)، أو وُجد في سورة تالية لأن عنوان السورة ناقص في المصدر (0.5).
- `marker`: الرقم وحده، أو عنوان السورة لنص قبل أول مقطع فيها (0.5، مربوط بالسورة كلها).
- `manual`: وضعه شخص في الأداة.

## تشغيل الأداة

المتطلبات: Flutter (المسار عندنا `~/development/flutter/bin/flutter`)، وGit LFS (ملفات المراجعة والخطوط فيه).

```sh
cd apps/review
flutter pub get
flutter run -d chrome          # للتجربة
# أو نسخة ثابتة تُرفع على أي خادم:
flutter build web
cd build/web && python3 -m http.server 8080   # ثم افتح http://localhost:8080
```

في الأداة:
1. اكتب اسمك واختر دورك، ثم «فتح ملف المراجعة» واختر مثلا `data/review/wahidi_asbab.review.db`. الملف يُفتح داخل المتصفح، ولا يُرفع إلى أي مكان.
2. القائمة على اليمين: صفِّ بالحالة، والنوع، والسورة، و«ثقة الربط أقل من 0.9»، أو ابحث في نص الكتاب.
3. على اليسار: نص الكتاب كما هو، وتحته كل ربط مع الآيات بخط المجمع. «ربط جديد» أو القلم لتغيير السورة والآيات، ويمكن اختيار كلمات من الآية بالضغط على أول كلمة ثم آخرها.
4. «حفظ التعديل» ثم «إرسال للمراجعة» (المحرر). «اعتماد» أو «رد مع ملاحظة» (المراجع).
5. **«حفظ الملف»** ينزّل الملف بعد التغييرات (المتصفح ينبه إن أغلقت الصفحة قبل الحفظ). ضعه مكان القديم في `data/review/` وسلّمه لمن يكمل. **يعمل على الملف شخص واحد في كل مرة.**

## الاستيراد والتصدير

```sh
python3 tools/fetch_sources.py openiti-wahidi-asbab-shamela0011314   # يتحقق من البصمة
python3 tools/import_wahidi_asbab.py        # ينشئ data/review/wahidi_asbab.review.db (يرفض الكتابة فوق ملف موجود: فيه عمل المراجعين)
python3 tools/export_pack.py data/review/wahidi_asbab.review.db --out data/packs/asbab_wahidi.pack.db
```

يطبع التصدير رسالة الـ commit وسطر `DATA_SOURCES.md`. ويرفض العمل إن لم يكن هناك مدخل مراجَع، أو إن فشل أي مدخل مراجَع في فحوصه.

الاختبارات:
```sh
python3 -m unittest discover -s tools/tests
cd apps/review && flutter test
```

## Supabase لاحقا

الخطة كانت مشروع Supabase منفصلا لقاعدة المراجعة. لا يوجد مشروع بعد، وإنشاؤه قرار أحمد. الأداة مبنية على واجهة تخزين (`ReviewStore`)، والمخزن المحلي يعمل الآن، والمخطط مع سياسات أمان الصفوف جاهز في `apps/review/supabase/` مع خطوات التفعيل.
